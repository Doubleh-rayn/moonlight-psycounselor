## 0. 작업 규칙

- 언어: 화면의 모든 문구는 한국어. 코드 주석은 한국어 또는 영어.
- 한 번에 한 단계만 구현한다. 요청하지 않은 기능을 미리 만들지 않는다.
- 비밀키는 `.env.local`에만 두고 커밋하지 않는다. `.env.example`을 만든다.
- 계산 로직(8절)은 화면과 분리된 순수 함수로 작성하고 단위 테스트(Vitest)를 붙인다.
- 확실하지 않은 사양은 추측해서 만들지 말고 나에게 질문한다.
- 각 단계 끝에 `npm run build`와 테스트가 통과하는지 확인한다.

## 1. 제품 개요

- 가족 구성원 전원(성인과 만 11세 자녀 포함, 2~5명)이 각자의 식단·운동·생활습관 목표를 퀘스트로 만들어 매일 체크하고, 스티커를 모아 보상으로 교환하는 가족 전용 웹앱.
- 한 가족만 사용한다. 다가족 서비스화는 범위 밖이다.
- 휴대폰과 PC 브라우저 모두에서 쓰는 반응형 PWA. 기준 화면 폭 390px.
- 기기 간 실시간 동기화가 필요하다.

## 2. 기술 스택

| 계층 | 선택 |
| --- | --- |
| 프레임워크 | Next.js (App Router) + TypeScript |
| 스타일 | Tailwind CSS. 6절의 디자인 토큰을 theme에 등록 |
| 폰트 | Pretendard (npm `pretendard` 패키지의 가변 폰트를 로컬 로드) |
| 백엔드 | Supabase (Postgres, Auth, Realtime) |
| 테스트 | Vitest |
| 배포 | GitHub 비공개 저장소 → Vercel 자동 배포 |

라이브러리 버전은 설치 시점의 안정 버전을 쓰고, 각 공식 문서의 현재 권장 방식을 따른다.

## 3. 계정과 권한 (단순화 방식)

가족 전용이므로 다음 구조로 단순화한다.

- 가족 계정 1개: Supabase Auth 이메일+비밀번호. 모든 기기에서 같은 계정으로 로그인한다.
- 로그인 후 프로필 선택 화면에서 구성원을 고른다(넷플릭스 방식). 선택한 구성원은 기기에 저장한다.
- 구성원 역할은 `admin`(성인) 또는 `member`.
- 관리자 전용 동작(승인, 보상 지급, 설정, 타인 기록 수정)은 관리자 PIN 4자리를 입력해야 실행된다. PIN은 해시로 저장한다.
- RLS: 모든 테이블에 "행의 family가 로그인한 계정 소유일 때만 읽기·쓰기 허용" 정책을 건다.

### 공개 범위

- 항목별 달성 현황, 진행률, 달성률, 체중 기록, 열량 가이드는 **가족 전원이 서로 볼 수 있다**(자녀 포함).
- 구성원 간 순위나 비교 표시는 만들지 않는다.
- 가족 외부에는 어떤 데이터도 공개되지 않는다.

## 4. 데이터 모델

```
              daily_deficit, diet_kcal, exercise_kcal, exercise_minutes_per_week, passed

cheers        id, from_member_id, to_member_id, date, message
```

규칙:
- 스티커 잔액은 저장하지 않는다. `완료된 checkins의 stickers 합 − 승인된 redemptions의 cost 합`으로 계산한다.
- 개인 스티커와 가족 스티커는 분리한다. 가족 공동 목표로 얻은 스티커는 `scope=family` 보상에만 쓴다.
- 목표는 삭제하지 않고 `active=false`로 비활성화한다. 과거 체크 기록은 유지한다.
- 날짜는 항상 한국 시간(Asia/Seoul) 기준으로 계산한다.

## 5. 기능 명세

### 5.1 오늘 (첫 화면)
- 상단: 날짜, 내 스티커 수, 현재 단계와 이번 주 실천율(70% 기준선 표시). 누르면 퀘스트 화면.
- 가족 주간 달성률 카드: 구성원별 원형 그래프(주간 달성률 %)와 "오늘 N / M". 구성원을 누르면 그 구성원의 기록 화면. 가족 공동 달성률은 막대로 별도 표시. 구성원은 `sort_order` 고정 순서로 나열하고 달성률로 정렬하지 않는다.
- 내 퀘스트 목록: 분류 아이콘 타일, 제목, 보조 설명, 체크 버튼. 한 번 탭으로 체크·해제.
- "습관 추가" 버튼.
- 가족 공동 퀘스트 카드: 참여 구성원 전원이 체크해야 성공. "3명 중 2명 완료" 표시.
- 응원 보내기: 다른 구성원에게 짧은 응원을 보낸다.
- 체크 수정은 당일과 전날까지만. 그 이전은 관리자 PIN 필요.

### 5.2 퀘스트 (단계 지도)
- 4단계: 적응 → 확장 → 강화 → 유지. 이전 단계를 통과해야 다음 단계가 열린다.
- 통과 조건: 해당 단계 기간의 **건강 퀘스트(diet, exercise) 실천율 70% 이상**. 생활습관(habit)은 통과 계산에서 제외한다.
- 미통과 시 벌칙 없이 같은 단계를 1주 연장한다.
- 이번 주 가이드 카드: 식단:운동 비율 막대, 식단 감소 kcal, 운동 증가 kcal, 주간 운동 분. "근사 계산에 따른 예상치이며 의료 처방이 아닙니다" 문구를 항상 표시한다.
- 단계 통과 시 보너스 스티커 5개와 배지.

### 5.3 기록
- 주간/월간 전환, 구성원 선택(나, 다른 구성원, 가족 공동).
- 요약: 전체, 건강, 생활습관 달성률.
- 항목별 주간 표: 요일별 완료 점, 항목별 "완료/예정" 횟수. 예정일 미완료는 작은 회색 점, 예정 없는 날은 빈칸. 빨간색 실패 표시는 쓰지 않는다.
- 횟수·분 단위 항목은 오늘 진행률 막대 표시(예: 20분 중 15분).
- 체중 기록(주 1회 권장)과 이번 주 열량 가이드. 가족 전원 조회 가능.
- 승인 대기 중인 제안 습관과 승인 버튼(관리자 PIN).

### 5.4 보상
- 내 스티커, 가족 스티커 잔액.
- 보상 목록: 필요 스티커 수, 진행 막대, "교환 신청" 버튼.
- 흐름: 신청(requested) → 관리자 승인(approved, 이때 스티커 차감) → 실제 지급 후 완료(fulfilled).
- 누구나 보상을 제안할 수 있고 관리자가 승인한다.
- 보상 추가 화면에 "음식은 보상으로 넣지 않기를 권장합니다" 안내 문구를 둔다.
- 연속 달성(스트릭)은 표시만 하고, 끊겨도 스티커를 차감하지 않는다.

### 5.5 습관 추가
- 분류: 식단, 운동, 정리정돈, 공부·독서, 수면, 기타.
- 분류별 추천 항목 버튼(코드에 고정 목록)과 직접 입력.
- 입력: 이름, 대상(본인/다른 구성원/가족 공동), 반복 요일 또는 주 N회, 측정 방식(완료 여부/횟수/분), 성공 시 스티커(1~2).
- 관리자가 추가하면 즉시 `approved`. 구성원이 추가하면 `proposed`이며 관리자 승인 후 시작.
- 동시 활성 한도: 구성원당 건강 5개, 생활습관 3개. 초과 시 안내 후 저장을 막는다.

### 5.6 설정 · 계획 만들기
- 구성원 관리(추가, 이름, 역할, 색상, 생년월, 성별, 키).
- 계획 만들기: 대상 구성원 선택 → 현재 체중, 목표 체중, 활동량 입력 → 8절 계산 결과를 주차별 표로 미리보기 → "이 계획으로 시작" 또는 "직접 수정".
- 계획을 시작하면 `plans`, `plan_weeks`를 저장하고, 현재 단계의 건강 퀘스트를 `source=plan`으로 자동 생성한다.
- 관리자는 목표 체중, 기간, 비율을 수정할 수 있으나 8.3의 한도를 넘는 값은 저장하지 않는다.

### 5.7 실시간 동기화
- `checkins`, `goals`, `redemptions`, `weight_logs`, `cheers` 변경을 Supabase Realtime으로 구독해 화면을 갱신한다.
- 체크는 낙관적 업데이트 후 실패 시 되돌린다.
- 오프라인이면 체크를 막고 "인터넷 연결이 필요합니다" 안내를 띄운다. 오프라인 저장은 만들지 않는다.

## 6. 디자인 시스템 — 입체 파스텔

원칙: 채도가 낮은 파스텔 단색 면 + 아래쪽 두꺼운 색 띠(edge)와 부드러운 그림자로 입체감. **그라데이션, 광택 하이라이트, 반투명 유리 효과는 쓰지 않는다.** 파스텔 면 위의 글자와 아이콘은 항상 진한 색(deep 또는 ink)을 쓴다. 흰 글자를 파스텔 위에 올리지 않는다.

### 입체 규칙
- 카드: `border-radius 20~24px`, `box-shadow: 0 4px 0 <edge>, 0 12px 18px rgba(90,100,160,0.10)`.
- 버튼·아이콘 타일·체크 버튼: `box-shadow: 0 3px 0 <edge>` (타일은 4px). 누르면 `translateY(2px)`와 함께 띠가 1px로 줄어든다.
- 아이콘 타일 48px, radius 15px. 체크 버튼 44px 원형. 모든 터치 영역 최소 44px.
- 상단 hero: 아래 모서리만 radius 32px, `0 6px 0 edge`.
- 하단 메뉴: 화면에서 떠 있는 둥근 막대(radius 26px, 좌우 여백 16px). 탭 5개: 오늘, 퀘스트, 기록, 보상, 설정.

### 타이포그래피와 아이콘
- 전부 Pretendard. 화면 제목 28px/800, 섹션 제목 16px/700, 본문 16px/600~700, 보조 13px/400~500.
- 아이콘은 선형(stroke) SVG, 굵기 2~2.2px. lucide-react 사용 가능. 이모지와 캐릭터 일러스트는 쓰지 않는다.
- 미달성 표시에 빨간색을 쓰지 않는다.

## 8. 계획 계산 로직 (`lib/plan/` 순수 함수)

모든 상수는 `lib/plan/constants.ts` 한 파일에 모은다. 이 수치들은 일반적으로 통용되는 근사값이며 의료 기준으로 검증된 값이 아니므로, 나중에 내가 바꿀 수 있게 상수로 분리해 둔다.

### 8.1 성인 (만 19세 이상)

```
총필요감량 kcal   = (현재체중 − 목표체중) × 7700
기간(주)          = ceil(감량kg ÷ 0.4), 최소 4주
단계 분할         = 적응: round(기간 × 0.25, 최소 1) / 확장: round(기간 × 0.375) / 강화: 나머지
기본 일일조정량 D = 총필요감량 ÷ (적응일수 × 2/3 + 나머지일수)
적응 단계 조정량  = D × 2/3,  확장·강화 단계 = D
식단:운동 비율    = 적응 8:2, 확장 7:3, 강화 6:4
운동 분당 소모    = 0.0175 × 4.3(MET, 빠르게 걷기) × 체중kg
주간 운동 분      = 운동kcal × 7 ÷ 분당소모
유지열량          = BMR × 활동계수(적음 1.2, 보통 1.375, 많음 1.55)
BMR(Mifflin-St Jeor) = 10×체중 + 6.25×키 − 5×나이 + (남 +5, 여 −161)
유지 단계         = 목표 도달 후 4주, 조정량 0, 통과 조건은 체중 ±1kg 유지
```

검증용 예시(단위 테스트로 작성): 60kg → 57kg, 체중 60kg 기준
- 기간 8주, 적응 2주 / 확장 3주 / 강화 3주
- 적응: 조정량 300, 식단 240, 운동 60, 주간 운동 약 93분
- 확장: 조정량 450, 식단 315, 운동 135, 주간 운동 약 209분
- 강화: 조정량 450, 식단 270, 운동 180, 주간 운동 약 279분
- 합계 300×14 + 450×42 = 23,100 kcal

### 8.2 미성년 (만 19세 미만)

```
기간(주)        = ceil(감량kg ÷ 0.125)        -- 월 약 0.5kg
일일조정량      = 감량kg × 7700 ÷ (기간 × 7)
식단:활동 비율  = 5:5 고정
단계 분할       = 성인과 같은 비율(0.25 / 0.375 / 나머지)
활동 목표       = 최종 단계에서 하루 60분을 목표로 단계적으로 증가
식단 조정 방식  = 끼니를 줄이지 않고 가당 음료·과자·야식을 대체하는 퀘스트만 생성
```

검증용 예시: 3kg 감량 → 24주, 일일 약 138 kcal, 식단 약 69 / 활동 약 69.

키는 월 1회 갱신 입력을 받고, 갱신 시 계획을 다시 계산한다.

### 8.3 한도 (위반 시 저장하지 않고 이유를 안내)

- 성인: 목표 체중의 BMI 18.5 미만이면 설정 불가.
- 성인: 일일조정량 500 kcal 초과 시 기간을 늘려 재계산.
- 성인: 식단 감소 후 섭취량이 여성 1,200 / 남성 1,500 kcal 미만이 되면 식단 감소분을 줄이고 기간을 늘린다.
- 미성년: 식단 감소분 하루 200 kcal 초과 불가. 감량 속도 월 1kg 초과 불가.
- 미성년: 현재 BMI가 연령·성별 85백분위수 미만이면 감량 계획 대신 유지 계획만 제공. 백분위수 표는 `data/bmi-percentiles.json`에서 읽는다. **이 파일의 수치는 지어내지 말고 빈 구조만 만들어라.** 내가 2017 소아청소년 성장도표 값을 직접 넣는다. 파일이 비어 있는 동안에는 이 검사를 건너뛰고 "성장도표 기준 미입력" 안내를 표시한다.
- 2주 연속 실제 감량이 계획보다 빠르면 조정량을 10% 낮춘다. 느리면 조정량은 그대로 두고 기간을 1주 늘린다.

### 8.4 계획에서 퀘스트 생성

식단 감소분과 운동 증가분을 행동 퀘스트로 바꾼다. 음식별 칼로리 입력 기능은 만들지 않는다.

| 퀘스트 예시 | 근사 kcal |
| --- | --- |
| 가당 음료 1잔을 물로 바꾸기 | 120 |
| 밥 3분의 1공기 덜기 | 100 |
| 과자·야식 1회 건너뛰기 | 150 |
| 빠르게 걷기 N분 | 분당소모 × N |

단계의 식단 kcal에 가깝게 식단 퀘스트를 조합하고, 운동은 주간 운동 분을 주 3~5회로 나눠 "빠르게 걷기 N분, 주 M회" 퀘스트로 만든다.

## 9. 개발 단계

각 단계를 끝내면 멈추고 완료 기준을 내가 확인할 수 있게 안내하라.

**1단계 — 뼈대와 디자인 시스템**
Next.js 프로젝트 생성, Tailwind에 6절 토큰 등록, Pretendard 적용, 공통 컴포넌트(Card, Button, IconTile, CheckButton, ProgressRing, ProgressBar, TabBar) 제작. 임시 데이터로 "오늘" 화면을 정적으로 완성.
완료 기준: `npm run dev`에서 390px 폭으로 오늘 화면이 6절 규칙대로 보인다.

**2단계 — 데이터베이스**
4절 스키마를 Supabase 마이그레이션 SQL로 작성, RLS 정책 적용, 타입 생성. 실행 방법을 안내.
완료 기준: 다른 계정으로 로그인하면 데이터가 조회되지 않는다.

**3단계 — 로그인과 프로필**
로그인, 최초 가족 생성(이름, 관리자 PIN, 구성원 등록), 프로필 선택, 관리자 PIN 확인 모달.
완료 기준: 두 기기에서 같은 계정으로 로그인해 서로 다른 구성원을 선택할 수 있다.

**4단계 — 퀘스트 체크와 실시간 동기화**
목표 CRUD, 오늘 화면 실데이터 연결, 체크·해제, 가족 공동 퀘스트, Realtime 구독.
완료 기준: 한 기기에서 체크하면 다른 기기 화면이 새로고침 없이 바뀐다.

**5단계 — 달성률과 기록**
주간 달성률 계산, 오늘 화면의 가족 달성률 카드, 기록 화면(주간/월간, 구성원 선택, 분류별 요약, 항목별 표, 진행률).
완료 기준: 자녀 프로필의 생활습관 항목별 달성 현황이 부모 프로필에서 보인다.

**6단계 — 스티커와 보상**
잔액 계산, 보상 CRUD, 교환 신청·승인·지급, 응원 보내기.
완료 기준: 잔액이 체크 수와 교환 내역으로 정확히 계산되고, 승인에 관리자 PIN이 필요하다.

**7단계 — 계획 계산과 퀘스트 지도**
8절 순수 함수와 단위 테스트, 계획 만들기 화면, plan_weeks 저장, 퀘스트 자동 생성, 단계 지도, 단계 통과 판정, 체중 기록.
완료 기준: 8.1과 8.2의 검증용 예시가 테스트로 통과한다.

**8단계 — 습관 추가와 승인**
습관 추가 화면, 추천 항목, 제안·승인 흐름, 동시 활성 한도.
완료 기준: 자녀 프로필에서 제안한 습관이 부모 프로필의 승인 후 오늘 화면에 나타난다.

**9단계 — PWA와 배포**
manifest, 아이콘, 홈 화면 설치, 빈 상태·로딩·오류 화면 정리, Vercel 배포 안내.
완료 기준: 휴대폰 홈 화면에 설치해 실행된다.
