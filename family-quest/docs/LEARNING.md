# 학습 체크리스트 — 가족 퀘스트 앱

단계마다 "이해해야 할 것"을 적고, 본인이 설명할 수 있으면 체크한다.
각 항목은 **왜(why) → 무엇(what) → 어떻게(how)** 순서로 확인한다.

## 1단계 — 뼈대와 디자인 시스템

### A. 문제 (왜 이 단계가 먼저인가)
- [ ] 왜 데이터베이스보다 디자인 시스템을 먼저 만드는가 (이후 모든 화면이 같은 부품을 쓰므로, 부품이 늦게 바뀌면 전 화면을 고쳐야 한다)
- [ ] 왜 "토큰(면/edge/deep 3단)"으로 색을 관리하는가 (색을 바꿀 때 한 곳만 수정, 파스텔 위 글자색을 자동으로 진하게 보장)
- [ ] 왜 날짜를 기기 시간이 아니라 Asia/Seoul 기준으로 고정하는가 (서버는 UTC, 체크 기록의 "오늘"이 어긋나면 달성률이 틀어진다)

### B. 해결 (무엇을, 어떻게)
- [ ] 폴더 구조: `src/app`(경로) / `src/components/ui`(공통 부품) / `src/components/today`(오늘 화면 전용) / `src/lib`(순수 로직·데이터)
- [ ] 디자인 토큰이 어디에 정의되는가: `src/app/globals.css` 의 `@theme static` → CSS 변수 `--color-hero` 등
- [ ] `toneStyle(tone)` 이 하는 일: 톤 이름 하나로 `--face / --edge / --deep` 세 변수를 요소에 주입
- [ ] `raised-card / raised-3 / raised-4 / raised-hero` 유틸리티가 각각 어떤 입체 규칙(6절)을 구현하는가
- [ ] 7개 공통 부품의 역할과 props: Card, Button, IconTile, CheckButton, ProgressRing, ProgressBar, TabBar
- [ ] Pretendard 를 왜 `next/font/local` 로 로드하는가 (외부 요청 없이 자체 호스팅, 글꼴 깜빡임 방지)

### C. 설계 결정과 엣지 케이스
- [ ] 결정 1: 기존 저장소 루트 대신 `family-quest/` 하위 폴더에 앱을 둔 이유
- [ ] 결정 2: 오늘 날짜를 서버가 아닌 클라이언트에서만 읽는 이유 (`useSeoulToday`, Cache Components 의 "현재시각" 제한 + 하이드레이션 불일치 회피)
- [ ] 결정 3: Tailwind v4 는 클래스에서 참조되지 않는 테마 변수를 지운다 → `@theme static` 으로 모든 토큰을 강제 출력 (실제로 겪은 버그)
- [ ] 결정 4: CSS 변수 색은 `bg-(--face)` 문법을 써야 한다 (`bg-[var(--face)]` 는 v4 에서 배경색으로 인식되지 않았다)
- [ ] 엣지: lavender 구성원의 그래프 선 색이 명세(6절)에 없음 → edge 색으로 임시 대체, 확정 필요
- [ ] 엣지: 체크 토글은 1단계에서 화면 상태만 바뀐다 (저장 없음). 4단계에서 낙관적 업데이트로 교체
- [ ] 엣지: 가족 공동 퀘스트는 "참여자 전원 체크 = 성공". 비참여 구성원에게는 체크 버튼이 보이지 않는다

### D. 넓은 맥락 (이 변경이 무엇에 영향을 주는가)
- [ ] 이후 모든 화면(퀘스트, 기록, 보상, 설정)이 이 7개 부품과 토큰만으로 조립된다
- [ ] 임시 데이터(`src/lib/mock/today.ts`)의 필드명이 4절 데이터 모델과 같으므로 4단계에서 교체 비용이 낮다
- [ ] `npm run build` / `npm test` / `npm run lint` 가 단계 종료의 공통 완료 기준이다

## 자가 점검 질문 (답을 적어 보기)

2. UTC 기준 2026-10-10 16:00 에 체크하면 `checkins.date` 에는 어떤 날짜가 들어가야 하는가? 그 이유는?
3. `@theme` 을 `@theme static` 으로 바꾸지 않았을 때 화면에서 무엇이 잘못 보였는가?
4. 구성원 순서를 달성률순으로 정렬하지 않는 이유는 어느 문서의 어느 절에 있는가?
